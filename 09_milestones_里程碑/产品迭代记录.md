## 2026-08-30 · 后台积分消耗页修复（用户名列 + 成本恒为 0）

**需求来源**：用户截图反馈后台「积分消耗」页两个问题：①「用户」列显示 user_id（user_f997871e48d6）不直观，要求改成用户名；②「成本(¥)」列所有记录恒为 0，但每条都有 input/output tokens。

### 根因分析（代码层面排查结论）
1. **用户名列**：`/v1/admin/usage` 端点只查 `usage_records` 表返回 `user_id`，前端 `AdminUsage.tsx` 直接渲染 `r.user_id`。
2. **成本为 0**：`model_pricing` 表唯一记录是 `qwen3.7-plus`（早期内部测试模型名），而所有流水的 `model_name` 实际都是 `qwen-plus`；`compute_cost_cny` 按 `model == model_name` 精确匹配，查不到即返回 0.0。扣费与积分逻辑本身无 bug（`charge()` 正确传 tokens/model_name 并同步减余额）。

### 改动点
1. **种子数据补 qwen-plus 定价**（`apps/api/app/database.py`）
   - `DEFAULT_MODEL_PRICING` 新增 `price_qwen_plus`：input ¥0.8 / output ¥2.0（阿里云百炼 qwen-plus 稳定版非思考输出官方价）。
   - 保留 `qwen3.7-plus` 历史行不删（旧流水可能引用）。
   - 启动时 `_seed_membership_data` upsert 自动写入，已有部署重启即生效，无需手工 SQL。
2. **后端流水返回 username**（`apps/api/app/admin_routes.py`）
   - `list_all_usage` 改为 `select(UsageRecord, User.username).outerjoin(User, UsageRecord.user_id == User.id)`（User 主键字段名是 `id` 不是 `user_id`，此处踩过一次 AttributeError）。
   - LEFT JOIN 保证用户被删除后流水仍可见（username=None，前端回退显示 user_id）。
3. **前端显示用户名**（`apps/web/lib/types.ts` + `apps/web/components/AdminUsage.tsx`）
   - `AdminUsageRecord` 增加 `username: string | null`。
   - 用户列渲染 `r.username ?? r.user_id`，`title` 悬浮显示完整 user_id 便于排查。

## 2026-08-30 · dev 环境登录 404 HTML 修复（next.config rewrites）

**需求来源**：用户截图反馈本地 dev（http://127.0.0.1:3230/）登录报「Unexpected token '<' … <!DOCTYPE」，确认方案 A 后实施。

### 根因
`next dev` 启动时 `NEXT_PUBLIC_API_BASE_URL` 未设置，`next.config.ts` 构建期兜底为 `/api`；dev 模式没有 nginx 反代，`/api/v1/auth/login` 被 Next.js 路由接管返回 404 HTML，前端 `parseJson` 解析 HTML 抛错。后端 8010 本身正常（curl 直连返回 401 JSON）。

### 改动点
- `apps/web/next.config.ts` 新增 `rewrites()`：`{ source: "/api/:path*", destination: "${API_PROXY_TARGET || 'http://127.0.0.1:8010'}/:path*" }`。

### 生产包安全性（实测证据，非口头保证）
- 复刻 `deploy-console/update-from-tar.sh` 发布自检：客户端 `.next/static/chunks/` 无 `NEXT_PUBLIC_API_BASE_URL` 残留、无 `:8010` 残留（连裸 8010 都没有）。
- rewrites 目标地址只存在于服务端 `routes-manifest.json`（afterFiles），不进客户端 bundle。
- 生产 nginx（`ec2-deploy.sh:264`）`location /api/` 在请求到达 Next.js 前已 proxy_pass 到 127.0.0.1:8010，rewrites 永不触发；即使 nginx 配置异常导致 /api 落到 Next.js，rewrites 转发到同机 8010 反而多一层兜底。
- `NEXT_PUBLIC_API_BASE_URL=/api next build --webpack`（部署脚本同款命令）构建成功。

### 验证
- dev：`POST 127.0.0.1:3230/api/v1/auth/login` → 401 `application/json`（修复前 404 HTML）；`/api/v1/account/quota` → 401 JSON。
- 后端 `/v1/auth/login` 直连始终正常（401 JSON），问题只在浏览器请求路径。
